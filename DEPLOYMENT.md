# Deployment — Vercel + Supabase

Lazy Frames has two halves:

| Part | Where it runs | Why |
|---|---|---|
| **CLI / render engine** (`packages/*`) | Local machine only | Needs headless Chrome + ffmpeg; byte-stable rendering is a local guarantee |
| **Website** (`docs/`) | **Vercel** (project `lazy-frames`, team `minhnga2910`) | Static landing page, plugin marketplace, docs, `skill.md` |
| **Plugin registry** | **Supabase** (project `lazy-frames`, ref `wessponwfhkhquiqtcyp`) | The registry used to be only the static `docs/plugins/index.json`; it now also lives in table `public.plugins` |

## Vercel

- Project: `lazy-frames`, connected to GitHub repo `minhnga2910/lazy-frames`.
- Root Directory: `docs`; Framework Preset: Other; no build command (files are
  prerendered — the marketplace HTML/JSON is generated by
  `npm run plugins:build` and committed).
- Production branch: `main`. **Every other branch/PR gets its own Preview
  deployment automatically.**
- Production URL: <https://lazy-frames-minhnga2910.vercel.app>
  (the previous custom domain `lazy-frames.cosmicstack.ai` still points at the
  old GitHub Pages host — move its DNS to Vercel to use it here).

Environment variables set on the Vercel project (all targets — Production,
Preview, Development):

| Key | Value | Notes |
|---|---|---|
| `SUPABASE_URL` | `https://wessponwfhkhquiqtcyp.supabase.co` | Public project URL |
| `SUPABASE_PUBLISHABLE_KEY` | `sb_publishable_…` | Browser-safe key (see below) |

## Supabase

- Project `lazy-frames` (org `minhnga2910`, region `ap-southeast-1`).
- Table **`public.plugins`** mirrors the registry: one row per plugin,
  full manifest stored in the `manifest jsonb` column. Schema:
  [`Supabase/migrations/20261103000000_plugin_registry.sql`](Supabase/migrations/20261103000000_plugin_registry.sql).
- **Row Level Security is on**: `anon`/`authenticated` can only `SELECT`.
  Writes happen only with the service-role key (sync script, CI) — there are
  no insert/update/delete policies for the public roles.

### How the marketplace uses it

`docs/plugins/marketplace.js` is a progressive enhancement:

1. Cards are prerendered statically at build time (works with JS off, works
   offline, stays byte-stable).
2. If `docs/plugins/supabase-config.js` is present, the browser refetches
   `GET /rest/v1/plugins` from Supabase and re-renders the grid live
   (eyebrow shows "live from Supabase").
3. Any failure silently keeps the static cards.

The publishable key in `supabase-config.js` is **safe to commit** — it only
gets the read-only RLS access above. The service-role key must **never** be
committed or shipped to the browser.

### Syncing after a plugin manifest change

```bash
npm run plugins:build          # regenerate docs/plugins from plugins/*/manifest.json
SUPABASE_URL="https://wessponwfhkhquiqtcyp.supabase.co" \
SUPABASE_SERVICE_ROLE_KEY="<from Supabase dashboard → Settings → API>" \
npm run plugins:sync-supabase  # upsert registry into public.plugins
```
